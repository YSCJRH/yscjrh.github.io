Why The Homepage Needed A Second Pass 为什么首页需要第二次优化

Working note 工作笔记

This is a short build log about why the site moved from solving structure first to strengthening credibility, readability, and public evidence. 这是一篇简短的构建日志，记录这张网站为什么会从“先把结构搭起来”转向“优先增强可信度、可读性和公开证据”。

What the first version already solved 第一版已经解决了什么

The first version solved the structure problem. It put Hero, Research, Build, Notes, and About on one page and already made the overall identity readable. 第一版解决的是结构问题。它把 Hero、Research、Build、Notes 和 About 放到了同一张页面上，也已经让整体身份变得可读。

That mattered, because before a site can become persuasive, it first has to become coherent. 这一步很重要，因为一个网站想要变得有说服力，前提是它先得是连贯的。

What the second pass was really about 第二次优化真正要解决什么

The second pass was less about style and more about credibility. The earlier version still carried some landing-page habits that made the site feel more like a polished product surface than a mature personal research/build homepage. 第二次优化更少是为了“风格”，更多是为了“可信度”。前一版仍然带着一些 landing page 的惯性，让它更像一个打磨过的产品表面，而不是一个成熟的个人研究 / 构建主页。

The real task was to make the page quieter, tighter, and more faithful to the amount of public proof that actually exists today. 真正的任务，是让页面变得更克制、更紧凑，也更贴近目前已经公开存在的那部分证据。

The main adjustments 这一轮的主要调整

  • Reduce the Hero scale so the page introduces a person before it introduces a visual effect. 把 Hero 缩回来，让页面先介绍“人”，再介绍视觉效果。
  • Replace repeated teaser logic with one compact direction panel. 用一个更紧凑的方向面板替代重复的 teaser 逻辑。
  • Turn Build cards from repository summaries into clearer evidence of working style. 让 Build 卡片从仓库摘要转向更清楚的工作方式与证据展示。
  • Keep Notes as a deliberate thinking surface instead of a placeholder content bucket. 把 Notes 保持成一个有意保留的思考界面，而不是占位内容区。
  • Make GitHub the clearest public action path without pretending there is already a fuller contact system. 让 GitHub 成为最清楚的公开行动入口，而不是假装已经具备更完整的联系系统。

The guiding rule 背后的规则

Remove anything that looks more certain, louder, or more productized than the current public evidence can support. 删掉一切比现有公开证据更确定、更响亮、也更“产品化”的部分。

That rule is useful beyond this page. It is also a good rule for project storytelling, note publishing, and how a personal research/build identity becomes trustworthy over time. 这条规则不只适用于这张首页。它同样适用于项目叙事、笔记发布，以及一个个人研究 / 构建身份如何在时间里慢慢建立可信度。
