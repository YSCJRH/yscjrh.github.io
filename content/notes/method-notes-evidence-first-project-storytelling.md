# Method Notes
## A Small Rule For Project Storytelling

Status: draft method note

### EN

When a personal homepage shows projects, the hardest mistake is usually not weak design. It is overstating what a repository proves.

A useful small rule is to write each project card through three short questions:

1. What does this project explore?
2. Why does that matter?
3. What does it suggest about the builder?

The first answer should stay close to the repository description and README.

The second can connect the project to a larger workflow or constraint, but it should still be visible from public materials.

The third is where tone matters most. It should describe a builder preference or working style, not an achievement that has not been publicly earned yet.

If a stronger story needs private context, the right move is not to guess. The right move is to record the gap and wait for better source material.

### 中文

当个人主页开始展示项目时，最容易犯的错误通常不是设计太弱，而是把一个仓库“能证明什么”说得太满。

一个很实用的小规则，是让每张项目卡都先回答三个短问题：

1. 这个项目在探索什么？
2. 这件事为什么重要？
3. 它体现出这个构建者的什么倾向？

第一个问题应该尽量贴着仓库 description 和 README 来写。

第二个问题可以把项目放回更大的工作流或现实约束里，但仍然要能从公开材料中看出来。

第三个问题最需要克制。它应该描述一种构建偏好或工作方式，而不是替项目提前写出还没有被公开证明的成就。

如果一个更强的故事需要私人上下文，正确做法不是猜，而是先把缺口记下来，等待更好的来源。
